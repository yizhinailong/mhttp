# 路由匹配核心

`mhttp::detail::RouteTree` 是不依赖网络的内部组件，注册方法、模式和调用方管理的
handler 标识符，匹配时返回拥有所有权的 `RouteMatch`。它尚未执行 handler 或写出响应；
服务端公共路由接口与 HTTP 会话将在后续阶段接入。

## 路径与匹配

注册路径以 `/` 开头，或为 OPTIONS 使用的字面量 `*`。
静态注册段使用已经解码的字节；例如 `/hello world` 匹配请求路径 `/hello%20world`。
请求路径须先去掉查询和片段，随后先按 `/` 切分再逐段百分号解码。
因此 `/files/a%2Fb` 可匹配 `/files/:name`，其中 `name` 是 `a/b`，
但它不会被视为 `/files/a/b`。路径中的 `+` 保持字面量；非法转义和末尾 `%` 原样保留，
解码得到的 NUL 也按有长度的字节字符串处理。

每个节点依次尝试静态、正则、参数、通配边；同一类别的动态边按注册顺序尝试。
路径后续段或方法不匹配时回溯，失败分支的参数不会留在匹配结果中。
再次注册完全相同的模式和方法会覆盖原标识符，保留它的匹配优先级。
参数名字不同的模式属于不同分支，例如 `/users/:id` 与 `/users/:name`。

`:name` 消费一个段，允许空字符串；`/users/:id` 匹配 `/users/`，但不匹配 `/users`。
`/prefix:suffix` 的中间冒号是静态字节。连续斜杠和末尾斜杠有意义，空段不会被丢弃。
终端 `*` 捕获剩余路径，名称为 `*`，并保留其中的空段和末尾斜杠；
`/files/*` 匹配 `/files/` 的空余部，但不匹配 `/files`。
参数名必须是非空 HTTP token，不能为 `*`，同一路径中的名字不能重复。

路径存在但方法不匹配时，结果状态为 405，`allow` 是所有完整候选路径允许的方法并集，
按方法字节序排序、去重，并为 GET 补充 HEAD；路径不存在时返回 404。
HEAD 先搜索所有显式 HEAD 候选，再按相同路径优先级搜索 GET；后者设置 `head_fallback`。
上层应将 `allow` 写入 `Allow` 头，并在 HEAD 响应中抑制 body。

## 正则与所有权

`{name:regex}` 匹配整个解码后的段，使用 ECMAScript 正则。
表达式在注册时编译，语法无效、来源超限或具有拒绝形态时返回 `InvalidRequest`，
不影响既有路由。默认来源上限为 256 字节，参与正则匹配的解码段上限为 1024 字节，
可通过建树时的 `RouteLimits` 配置。超长段跳过正则，仍可尝试参数或通配分支。

准入检查跳过转义和字符类，拒绝包含量词或交替的分组再次被量化，
包括 `(a+)+`、`((a+))+` 和 `(a|aa)+`。这是保守检查，不提供线性匹配时间保证。
运行时正则资源错误视为该分支不匹配。

节点由平坦容器拥有，搜索使用显式帧，深路径的匹配、回溯和销毁不会递归占用调用栈。
完成注册后允许多个线程同时调用 `Match`；每个结果独立拥有参数，后续匹配不会使其失效。
修改路由表需要外部同步。上层 Router 还需在运行期间拒绝注册，并在会话排空后才恢复修改。

`tests/server/route_pattern_test.cpp` 覆盖模式语法、危险正则、来源大小边界和路径解码；
`route_tree_test.cpp` 覆盖优先级、回溯、方法、HEAD、编码路径、正则匹配大小边界，
以及 3000 段路径和多线程只读匹配。HTTP 响应与 handler 行为仍需后续端到端测试。
